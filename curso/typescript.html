01 Objetivo e pré-requisitos

TypeScript acrescenta verificação estática ao JavaScript. Ele ajuda a detectar combinações incompatíveis durante o desenvolvimento, melhora a navegação do editor e documenta contratos. O código executado continua sendo JavaScript, e dados recebidos em tempo de execução ainda precisam de validação.

Nesta etapa, você não começará uma aplicação desconectada. Você migrará gradualmente o Café Horizonte criado nas apostilas anteriores. O cardápio fornece entidades concretas para tipar; o formulário fornece eventos e dados opcionais; e a API fornece uma fronteira externa que precisa de contrato e validação em runtime.

Você deve dominar funções, arrays, objetos, módulos e JavaScript assíncrono. Os capítulos finais também pressupõem componentes, props, estado e eventos em React.

Resultado da trilha até aqui

Apostila anteriorBase usada nesta apostila
HTML e CSSEstrutura semântica e formulário acessível.
JavaScriptFunções, arrays, objetos, módulos e validação.
ReactComponentes, props, estado, eventos e serviços.
Full StackContratos HTTP de cardápio e reservas.

A migração será concluída quando o comportamento permanecer igual, os tipos descreverem o domínio e nenhuma resposta externa for aceita apenas porque recebeu uma anotação TypeScript.

O que TypeScript não faz

JSON da API
Não valida automaticamente JSON recebido de uma API.
Lógica
Não impede todos os erros de lógica.
Testes
Não substitui testes.
Modelagem
Não transforma um modelo de dados impreciso em um bom modelo.
Anotações
Não exige anotar cada variável quando a inferência já é clara.

02 Primeiro projeto TypeScript

Para experimentar o compilador sem React:

mkdir typescript-basics
cd typescript-basics
npm init -y
npm install --save-dev typescript
npx tsc --init

Crie src/index.ts:

const courseName: string = "TypeScript aplicado";
const lessonCount: number = 10;

console.log(`${courseName} possui ${lessonCount} capítulos.`);

O compilador analisa o arquivo e produz JavaScript conforme a configuração. Em projetos React com Vite, a ferramenta transforma TypeScript durante o build, enquanto uma verificação separada pode ser executada pelo compilador.

Configuração consciente

Ative verificações estritas em projetos novos quando possível.

{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true
  }
}

Algumas opções exigem adaptação em código existente. Migre gradualmente e entenda cada erro antes de desativar uma proteção.

03 Inferência e tipos cotidianos

TypeScript infere muitos tipos pelo valor inicial.

const title = "GitHub Finder"; // string
let page = 1;                  // number
const loading = false;         // false em const e contexto apropriado

Uma anotação é útil quando a variável nasce sem valor suficiente, quando a função forma um contrato público ou quando a intenção precisa ser mais específica.

let selectedUser: string | null = null;

function formatUserName(name: string): string {
  return name.trim();
}

Arrays e objetos

const technologies: string[] = ["React", "TypeScript"];

type Project = {
  id: string;
  title: string;
  technologies: string[];
  published: boolean;
};

const project: Project = {
  id: "p1",
  title: "GitHub Finder",
  technologies: ["React", "TypeScript"],
  published: true,
};

Propriedades opcionais e somente leitura

type User = {
  readonly id: number;
  login: string;
  name?: string;
};

name?: string significa que a propriedade pode estar ausente. Isso não é sempre igual a uma propriedade obrigatória com valor string | undefined, especialmente com verificações mais estritas.

Type e interface

Ambos podem descrever objetos. Use uma convenção consistente. interface oferece extensão e declaração incremental; type também representa uniões, primitivas e composições.

interface Repository {
  id: number;
  name: string;
  stars: number;
}

type RequestStatus = "idle" | "loading" | "success" | "error";

04 Funções e contratos

function calculateTotal(price: number, quantity: number): number {
  return price * quantity;
}

function logError(message: string): void {
  console.error(message);
}

Parâmetros opcionais e valores padrão

function formatPrice(value: number, currency = "BRL"): string {
  return new Intl.NumberFormat("pt-BR", {
    style: "currency",
    currency,
  }).format(value);
}

Parâmetros opcionais aparecem depois dos obrigatórios.

function createLabel(text: string, color?: string): string {
  return color ? `${text} ${color}` : text;
}

Callbacks

type ProjectFilter = (project: Project) => boolean;

function filterProjects(
  projects: Project[],
  predicate: ProjectFilter,
): Project[] {
  return projects.filter(predicate);
}

Nomear contratos reutilizados costuma deixar assinaturas complexas mais legíveis.

05 Uniões e narrowing

Uma união representa alternativas conhecidas.

type SearchResult = User | null;

Antes de usar uma operação específica, reduza a união com uma verificação.

function showUser(user: User | null): string {
  if (user === null) {
    return "Usuário não encontrado";
  }
  return user.name ?? user.login;
}

Discriminated unions

Estados de requisição ficam mais precisos quando cada alternativa possui os dados compatíveis.

type LoadState<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; message: string };
function getMessage(state: LoadState<User>): string {
  switch (state.status) {
    case "idle":
      return "Digite um usuário";
    case "loading":
      return "Carregando";
    case "success":
      return state.data.login;
    case "error":
      return state.message;
  }
}

O campo status permite ao compilador saber quais propriedades existem em cada caso. Esse modelo evita estados impossíveis, como loading: true com dados antigos e erro simultâneo.

Unknown em fronteiras

Use unknown quando o valor realmente é desconhecido. Você precisa verificar antes de usar.

function isUser(value: unknown): value is User {
  if (typeof value !== "object" || value === null) return false;
  const candidate = value as Record<string, unknown>;
  return (
    typeof candidate.id === "number" &&
    typeof candidate.login === "string"
  );
}

Uma asserção como value as User não valida o valor. Ela apenas informa ao compilador que você assume aquele tipo.

06 Generics e utilitários

Generics preservam relações entre tipos sem usar any.

function firstItem<T>(items: T[]): T | undefined {
  return items[0];
}

const firstTechnology = firstItem(["React", "TypeScript"]);
const firstNumber = firstItem([10, 20, 30]);

Restrições

type WithId = { id: string | number };

function findById<T extends WithId>(items: T[], id: T["id"]): T | undefined {
  return items.find((item) => item.id === id);
}

Tipos utilitários

type NewProject = Omit<Project, "id" | "published">;
type ProjectUpdate = Partial<Pick<Project, "title" | "published">>;
type PublicProject = Readonly<Project>;
UtilitárioUso
Partial<T>Torna propriedades opcionais.
Required<T>Torna propriedades obrigatórias.
Pick<T, K>Seleciona propriedades.
Omit<T, K>Remove propriedades.
Readonly<T>Impede atribuição às propriedades no código tipado.
Record<K, V>Modela um objeto com chaves e valores definidos.

Não use utilitários para esconder um modelo confuso. Nomeie tipos de entrada e saída quando eles representam conceitos importantes.

07 APIs tipadas e validação em runtime

O tipo genérico abaixo descreve o valor esperado depois da validação. Ele não prova que a rede enviou esse formato.

async function requestJson(url: string): Promise<unknown> {
  const response = await fetch(url);

  if (!response.ok) {
    throw new Error(`Falha HTTP ${response.status}`);
  }

  return response.json();
}
async function getUser(login: string): Promise<User> {
  const data = await requestJson(`https://api.github.com/users/${login}`);

  if (!isUser(data)) {
    throw new Error("Resposta da API em formato inesperado");
  }

  return data;
}

Para modelos extensos, considere uma biblioteca de schema que produza validação em runtime e tipos, ou escreva validadores focados nos campos usados pela aplicação.

08 React com TypeScript

Crie um projeto Vite com o modelo React TypeScript:

npm create vite@latest github-finder -- --template react-ts
cd github-finder
npm install
npm run dev

Props

type UserCardProps = {
  user: User;
  onSelect?: (user: User) => void;
};

export function UserCard({ user, onSelect }: UserCardProps) {
  return (
    <article>
      <h2>{user.name ?? user.login}</h2>
      <p>@{user.login}</p>
      {onSelect && (
        <button type="button" onClick={() => onSelect(user)}>
          Selecionar
        </button>
      )}
    </article>
  );
}

Não use React.FC por hábito. Tipar as props diretamente costuma ser suficiente e deixa o retorno inferido.

Estado

const [query, setQuery] = useState("");
const [state, setState] = useState<LoadState<User>>({ status: "idle" });

O primeiro estado é inferido como string. O segundo precisa do tipo genérico porque pode assumir várias formas ao longo do tempo.

Eventos de formulário

import type { ChangeEvent, FormEvent } from "react";

function SearchForm() {
  const [query, setQuery] = useState("");

  function handleChange(event: ChangeEvent<HTMLInputElement>) {
    setQuery(event.target.value);
  }

  function handleSubmit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    console.log(query);
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="query">Usuário do GitHub</label>
      <input id="query" value={query} onChange={handleChange} />
      <button type="submit">Buscar</button>
    </form>
  );
}

Tipar o elemento específico melhora o acesso a target, currentTarget e propriedades disponíveis.

Children

import type { ReactNode } from "react";

type PanelProps = {
  title: string;
  children: ReactNode;
};

Use o tipo mais específico possível para a intenção. ReactNode serve para conteúdo renderizável variado.

Refs

const inputRef = useRef<HTMLInputElement>(null);

function focusInput() {
  inputRef.current?.focus();
}

return <input ref={inputRef} />;

O valor inicial é null porque o elemento ainda não existe durante a primeira execução do componente.

09 Reducers, contexto e hooks tipados

Reducer

type ProjectAction =
  | { type: "added"; project: Project }
  | { type: "removed"; projectId: string }
  | { type: "publishedToggled"; projectId: string };

function projectsReducer(
  state: Project[],
  action: ProjectAction,
): Project[] {
  switch (action.type) {
    case "added":
      return [...state, action.project];
    case "removed":
      return state.filter((project) => project.id !== action.projectId);
    case "publishedToggled":
      return state.map((project) =>
        project.id === action.projectId
          ? { ...project, published: !project.published }
          : project,
      );
  }
}

A união discriminada impede ações sem os dados exigidos.

Contexto

import { createContext, useContext } from "react";
import type { Dispatch } from "react";

type ProjectsContextValue = {
  projects: Project[];
  dispatch: Dispatch<ProjectAction>;
};

const ProjectsContext = createContext<ProjectsContextValue | null>(null);

export function useProjects() {
  const context = useContext(ProjectsContext);

  if (!context) {
    throw new Error("useProjects deve estar dentro de ProjectsProvider");
  }

  return context;
}

O hook remove null para consumidores depois de verificar o provider.

10 Migração gradual

Não é necessário converter toda a aplicação em uma única alteração.

Ordem recomendada

1
Configure o compilador e permita JavaScript durante a transição, se necessário.
2
Converta funções utilitárias puras.
3
Modele entidades e contratos de API.
4
Converta componentes de folha com props simples.
5
Converta formulários, contexto e reducers.
6
Substitua any temporários por tipos reais.
7
Ative verificações mais estritas gradualmente.

Tratando erros sem mascarar

any temporário
Não troque um erro por any sem registrar por que ele é temporário.
Asserções em cadeia
Evite asserções em cadeia como value as unknown as User.
null/undefined
Modele null e undefined quando fazem parte do domínio.
Fronteiras externas
Valide fronteiras externas.
Inferência
Prefira inferência local e contratos explícitos nas fronteiras.

11 Projeto guiado: migração do Café Horizonte

Comece pela entidade que atravessa todas as camadas:

export type MenuItem = {
  id: string;
  name: string;
  category: "bebidas" | "doces" | "salgados";
  price: number;
  available: boolean;
  imageUrl?: string;
};

export type ReservationInput = {
  name: string;
  email: string;
  date: string;
  time: string;
  people: number;
};

Ordem da migração do projeto

1
Renomeie utilitários puros de .js para .ts e corrija contratos sem usar any.
2
Converta MenuItemCard e MenuList, tipando props e callbacks.
3
Converta o filtro e faça a categoria aceitar somente valores permitidos.
4
Converta o formulário, tipando eventos e o estado dos campos.
5
Modele carregamento, sucesso, vazio e erro com união discriminada.
6
Faça o serviço da API receber unknown e validar os dados antes de devolver MenuItem[].
7
Converta contexto e reducer, se existirem.
8
Ative verificações estritas e elimine justificadamente os últimos tipos temporários.

O compilador não sabe se a API realmente devolveu um item válido. Uma função de validação deve confirmar os campos usados antes que o valor entre na aplicação.

export function isMenuItem(value: unknown): value is MenuItem {
  if (typeof value !== "object" || value === null) return false;
  const item = value as Record<string, unknown>;
  return (
    typeof item.id === "string" &&
    typeof item.name === "string" &&
    typeof item.price === "number" &&
    typeof item.available === "boolean"
  );
}

Critério de conclusão: alterar o contrato de MenuItem deve orientar o editor até os componentes e serviços afetados; receber JSON inválido deve produzir um erro controlado em runtime.

13 Formulário Multistep com TypeScript

Modele as etapas e os dados antes de criar componentes.

type FormData = {
  name: string;
  email: string;
  review: string;
  score: number | null;

type Step = "identity" | "review" | "confirmation";

14 Exercícios

Conversor de dados

Receba unknown, verifique se é um array de projetos e devolva Project[]. Não use any nem uma asserção sem validação.

Estado de upload

Modele com união discriminada os estados parado, enviando com progresso, sucesso e erro. Garanta que progresso só exista durante envio.

Componente de tabela

Crie props para uma tabela de repositórios com itens, função de seleção e mensagem vazia. Tipar um item como Repository deve orientar todas as props relacionadas.
