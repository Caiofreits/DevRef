01 Objetivo e limites

Esta apostila continua o Café Horizonte construído em HTML, CSS, JavaScript e React. Até aqui, o cardápio e as reservas existiam apenas no navegador ou em um servidor simulado. Agora você construirá uma API própria para armazenar itens do cardápio e solicitações de reserva, conectando-a ao front-end React.

Os projetos Party Time e Memories permanecem como estudos complementares do curso. Seus conceitos de CRUD, relacionamento e upload serão aplicados ao domínio do café, evitando que o aluno precise aprender back-end e um projeto totalmente novo ao mesmo tempo.

O material pressupõe JavaScript assíncrono, objetos, arrays, módulos, formulários e React. A aplicação é didática. Antes de produção, ainda seriam necessários autenticação, autorização, testes abrangentes, observabilidade, política de arquivos e revisão de segurança.

Arquitetura que será construída

Navegador (React)
      |
      | HTTP com JSON e arquivos
      v
API Café Horizonte (Node + Express)
      |
      | validação e operações
      v
MongoDB (por meio do Mongoose)

O navegador nunca deve receber a string de conexão do banco. O front-end conversa com a API, e a API controla o acesso aos dados.

02 HTTP antes do Express

Uma requisição contém método, endereço, cabeçalhos e, em alguns casos, corpo. A resposta contém status, cabeçalhos e corpo.

MétodoUso comumExemplo
GETLer dadosGET /api/menu-items
POSTCriar recursoPOST /api/reservations
PATCHAtualizar partePATCH /api/menu-items/:id
DELETERemover recursoDELETE /api/reservations/:id

Status importantes

StatusSignificado
200Requisição concluída com corpo de resposta.
201Recurso criado.
204Sucesso sem corpo.
400Dados da requisição são inválidos.
404Recurso não encontrado.
409Conflito com o estado existente.
500Falha inesperada no servidor.

Status não substitui uma mensagem útil, e a mensagem não substitui o status correto.

Formato de erro consistente

{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Revise os campos enviados",
    "details": {
      "name": "O nome é obrigatório"
    }
  }
}

Um formato previsível permite que o front-end trate erros sem depender de frases variadas.

03 Criando o servidor Node

Crie uma pasta separada para a API.

mkdir cafe-horizonte-api
cd cafe-horizonte-api
npm init -y
npm install express mongoose cors multer

Adicione ao package.json:

{
  "type": "module",
  "scripts": {
    "dev": "node --env-file=.env --watch src/server.js",
    "start": "node --env-file=.env src/server.js"
  }
}

Os recursos --watch e --env-file dependem da versão do Node instalada. Confirme a documentação da sua versão; em versões antigas, escolha ferramentas compatíveis e mantenha o mesmo contrato de variáveis.

04 Rotas, middleware e controladores

Middleware executa durante o caminho da requisição. Ele pode ler ou alterar a requisição, encerrar a resposta ou passar o controle adiante.

app.use((request, response, next) => {
  const startedAt = Date.now();

  response.on("finish", () => {
    const duration = Date.now() - startedAt;
    console.log(request.method, request.url, response.statusCode, duration);
  });

  next();
});

Nunca registre senhas, tokens, cookies ou corpos sensíveis em logs.

Router

// src/routes/menu.routes.js
import { Router } from "express";
import {
  createMenuItem,
  deleteMenuItem,
  listMenuItems,
  updateMenuItem,
} from "../controllers/menu.controller.js";
import { validateMenuItemBody } from "../middleware/validation.js";

export const menuRouter = Router();

menuRouter.get("/", listMenuItems);
menuRouter.post("/", validateMenuItemBody, createMenuItem);
menuRouter.patch("/:itemId", updateMenuItem);
menuRouter.delete("/:itemId", deleteMenuItem);
// src/app.js
import { menuRouter } from "./routes/menu.routes.js";

app.use("/api/menu-items", menuRouter);

Parâmetros, query e corpo

request.params
Contém valores da rota, como itemId.
request.query
Contém filtros da URL, como ?page=2.
request.body
Contém o corpo interpretado pelo middleware adequado.

Valide todos os três quando influenciam uma operação.

Validação da requisição antes do controlador

A validação de entrada merece um módulo próprio. Assim, o controlador cuida da operação e o middleware rejeita cedo um corpo inválido. A validação abaixo é didática; em projetos maiores, uma biblioteca de schemas pode reduzir repetição, desde que você compreenda o contrato produzido.

// src/middleware/validation.js
function validationError(response, details) {
  return response.status(400).json({
    error: {
      code: "VALIDATION_ERROR",
      message: "Revise os campos enviados",
      details,
    },
  });
}

export function validateMenuItemBody(request, response, next) {
  const { name, category, price } = request.body;
  const details = {};

  if (typeof name !== "string" || name.trim().length < 3) {
    details.name = "Informe um nome com ao menos três caracteres";
  }

  if (!["bebidas", "doces", "salgados"].includes(category)) {
    details.category = "Escolha uma categoria válida";
  }

  if (typeof price !== "number" || !Number.isFinite(price) || price < 0) {
    details.price = "Informe um preço numérico maior ou igual a zero";
  }

  if (Object.keys(details).length > 0) {
    return validationError(response, details);
  }

  request.body.name = name.trim();
  return next();
}

export function validateReservationBody(request, response, next) {
  const { name, email, date, time, people } = request.body;
  const details = {};

  if (typeof name !== "string" || name.trim().length < 3) {
    details.name = "Informe o nome da reserva";
  }

  if (typeof email !== "string" || !email.includes("@")) {
    details.email = "Informe um e-mail válido";
  }

  if (typeof date !== "string" || Number.isNaN(Date.parse(date))) {
    details.date = "Informe uma data válida";
  }

  if (typeof time !== "string" || !/^([01]\d|2[0-3]):[0-5]\d$/.test(time)) {
    details.time = "Use o formato HH:MM";
  }

  if (!Number.isInteger(people) || people < 1 || people > 12) {
    details.people = "Escolha entre 1 e 12 pessoas";
  }

  if (Object.keys(details).length > 0) {
    return validationError(response, details);
  }

  request.body.name = name.trim();
  request.body.email = email.trim().toLowerCase();
  return next();
}

Validar formato não basta para todas as regras. A data pode estar bem formada e ainda estar no passado; um horário pode estar correto e fora do expediente. Essas regras de negócio devem ser testadas no servidor.

05 MongoDB e Mongoose

MongoDB armazena documentos em coleções. Mongoose adiciona schemas, modelos, validação e uma camada de acesso orientada a objetos.

Variáveis de ambiente

PORT=3000
MONGODB_URI=mongodb://127.0.0.1:27017/cafe_horizonte
CLIENT_ORIGIN=http://localhost:5173

Não envie o arquivo com segredos ao repositório. Mantenha um .env.example com apenas os nomes e exemplos não sensíveis. Inclua ao menos .env, node_modules/ e os arquivos locais de uploads/ no .gitignore. Se o diretório de upload precisar existir no repositório, mantenha apenas um arquivo marcador sem conteúdo privado.

Conexão

// src/database.js
import mongoose from "mongoose";

export async function connectDatabase(uri) {
  if (!uri) {
    throw new Error("MONGODB_URI não configurada");
  }

  await mongoose.connect(uri);
  console.log("Banco conectado");
}
// src/server.js
import { app } from "./app.js";
import { connectDatabase } from "./database.js";

const port = process.env.PORT ?? 3000;

try {
  await connectDatabase(process.env.MONGODB_URI);
  app.listen(port, () => console.log(`API na porta ${port}`));
} catch (error) {
  console.error("Falha ao iniciar a API", error);
  process.exit(1);
}

O servidor só começa a aceitar requisições depois de conectar ao banco.

const menuItemSchema = new mongoose.Schema(

Listagem

Criação

export async function createMenuItem(request, response, next) {
  try {
    const { name, category, price } = request.body;
    const item = await MenuItem.create({
      name,
      category,
      price,
      imagePath: request.body.imagePath ?? null,
    });
    return response.status(201).json({ data: item });
  } catch (error) {
    return next(error);
  }
}

O middleware já validou e normalizou o corpo. O schema continua sendo a segunda barreira e protege também gravações feitas por outros caminhos internos.

Atualização parcial

Uma atualização parcial deve aceitar somente campos conhecidos. Não passe o corpo inteiro diretamente para o banco.

import mongoose from "mongoose";

export async function updateMenuItem(request, response, next) {
  try {
    const { itemId } = request.params;

    if (!mongoose.isValidObjectId(itemId)) {
      return response.status(400).json({
        error: { code: "INVALID_ID", message: "Identificador inválido" },
      });
    }

    const allowedFields = ["name", "category", "price", "available"];
    const changes = Object.fromEntries(
      Object.entries(request.body).filter(([key]) => allowedFields.includes(key)),
    );

    if (Object.keys(changes).length === 0) {
      return response.status(400).json({
        error: { code: "EMPTY_UPDATE", message: "Nenhum campo permitido enviado" },
      });
    }

    const item = await MenuItem.findByIdAndUpdate(itemId, changes, {
      new: true,
      runValidators: true,
    });

    if (!item) {
      return response.status(404).json({
        error: { code: "NOT_FOUND", message: "Item não encontrado" },
      });
    }

    return response.status(200).json({ data: item });
  } catch (error) {
    return next(error);
  }
}

runValidators: true aplica validações do schema também na atualização. Para regras detalhadas de PATCH, crie um middleware específico que valide apenas os campos presentes.

Módulo de reservas

// src/controllers/reservation.controller.js
import mongoose from "mongoose";
import { Reservation } from "../models/Reservation.js";

export async function createReservation(request, response, next) {
  try {
    const requestedDate = new Date(request.body.date);

    if (requestedDate < new Date()) {
      return response.status(400).json({
        error: {
          code: "RESERVATION_DATE_IN_PAST",
          message: "A reserva deve ser feita para uma data futura",
        },
      });
    }

    const reservation = await Reservation.create({
      ...request.body,
      date: requestedDate,
    });

    return response.status(201).json({ data: reservation });
  } catch (error) {
    return next(error);
  }
}

export async function getReservation(request, response, next) {
  try {
    if (!mongoose.isValidObjectId(request.params.reservationId)) {
      return response.status(400).json({
        error: { code: "INVALID_ID", message: "Identificador inválido" },
      });
    }

    const reservation = await Reservation.findById(
      request.params.reservationId,
    ).lean();

    if (!reservation) {
      return response.status(404).json({
        error: { code: "NOT_FOUND", message: "Reserva não encontrada" },
      });
    }

    return response.status(200).json({ data: reservation });
  } catch (error) {
    return next(error);
  }
}

export async function deleteReservation(request, response, next) {
  try {
    if (!mongoose.isValidObjectId(request.params.reservationId)) {
      return response.status(400).json({
        error: { code: "INVALID_ID", message: "Identificador inválido" },
      });
    }

    const reservation = await Reservation.findByIdAndDelete(
      request.params.reservationId,
    );

    if (!reservation) {
      return response.status(404).json({
        error: { code: "NOT_FOUND", message: "Reserva não encontrada" },
      });
    }

    return response.status(204).send();
  } catch (error) {
    return next(error);
  }
}

import { Router } from "express";

07 Tratamento centralizado de erros

Rotas não devem repetir a mesma conversão de erros inesperados.

export function notFound(request, response) {
  response.status(404).json({
    error: { code: "ROUTE_NOT_FOUND", message: "Rota não encontrada" },
  });
}

export function errorHandler(error, request, response, next) {
  console.error(error);

  if (error.name === "ValidationError") {
    return response.status(400).json({
      error: { code: "VALIDATION_ERROR", message: error.message },
    });
  }

  return response.status(500).json({
    error: { code: "INTERNAL_ERROR", message: "Falha interna" },
  });
}

Registre os middlewares depois das rotas.

app.use(notFound);
app.use(errorHandler);

Não devolva pilhas de erro nem detalhes internos ao cliente em produção.

Montagem final da aplicação

A ordem dos middlewares faz parte do comportamento. Interprete o corpo e aplique CORS antes das rotas; deixe rota inexistente e erro por último.

// src/app.js
import cors from "cors";
import express from "express";
import { errorHandler, notFound } from "./middleware/errors.js";
import { menuRouter } from "./routes/menu.routes.js";
import { reservationRouter } from "./routes/reservation.routes.js";

export const app = express();

app.use(cors({ origin: process.env.CLIENT_ORIGIN }));
app.use(express.json({ limit: "1mb" }));

app.get("/health", (request, response) => {
  response.status(200).json({ status: "ok" });
});

app.use("/api/menu-items", menuRouter);
app.use("/api/reservations", reservationRouter);

app.use(notFound);
app.use(errorHandler);

08 CORS e integração com React

CORS controla quais origens podem ler respostas do navegador. Ele não é um mecanismo de autenticação.

app.use(
  cors({

Serviço no front end

const API_URL = import.meta.env.VITE_API_URL;

async function request(path, options = {}) {
  const response = await fetch(`${API_URL}${path}`, {
    ...options,
    headers: {
      "Content-Type": "application/json",
      ...options.headers,
    },
  });

  if (!response.ok) {
    const body = await response.json().catch(() => null);
    throw new Error(body?.error?.message ?? `Falha HTTP ${response.status}`);
  }

  if (response.status === 204) return null;
  return response.json();
}

export async function getMenuItems() {
  const body = await request("/api/menu-items");
  return body.data;
}

export async function postReservation(input) {
  const body = await request("/api/reservations", {
    method: "POST",
    body: JSON.stringify(input),
  });
  return body.data;
}

Variáveis com prefixo VITE_ são incorporadas ao front-end e ficam visíveis ao navegador. Nunca coloque segredos nelas.

09 Upload de arquivos

Uploads precisam de limites, nomes gerados pelo servidor, validação de conteúdo e estratégia de armazenamento. O exemplo local usa extensão e MIME declarado como filtros iniciais. Eles não substituem a inspeção da assinatura do arquivo, a varredura e as políticas exigidas em produção.

import path from "node:path";
import { randomUUID } from "node:crypto";
import multer from "multer";

const allowedExtensions = new Set([".jpg", ".jpeg", ".png", ".webp"]);
const allowedMimeTypes = new Set(["image/jpeg", "image/png", "image/webp"]);

const storage = multer.diskStorage({
  destination: "uploads/",
  filename(request, file, callback) {
    const extension = path.extname(file.originalname).toLowerCase();

    if (!allowedExtensions.has(extension)) {
      return callback(new Error("Extensão de arquivo não permitida"));
    }

    return callback(null, `${randomUUID()}${extension}`);
  },
});

export const upload = multer({
  storage,
  limits: { fileSize: 5 * 1024 * 1024 },
  fileFilter(request, file, callback) {
    callback(null, allowedMimeTypes.has(file.mimetype));
  },
});
function normalizeMultipartMenuItem(request, response, next) {
  if (typeof request.body.price === "string") {
    request.body.price = Number(request.body.price);
  }

  request.body.imagePath = request.file?.path ?? null;
  next();
}

// Substitua a rota POST anterior por esta ao habilitar upload.
menuRouter.post(
  "/",
  upload.single("image"),
  normalizeMultipartMenuItem,
  validateMenuItemBody,
  createMenuItem,
);

No front-end, envie FormData e não defina manualmente Content-Type; o navegador precisa incluir o boundary correto.

const formData = new FormData();
formData.append("name", name);
formData.append("category", category);
formData.append("price", String(price));
formData.append("image", file);

await fetch(`${API_URL}/api/menu-items`, {
  method: "POST",
  body: formData,
});

Em produção, considere armazenamento de objetos, varredura, política de retenção e remoção do arquivo quando o registro for apagado.

10 Segurança e manutenção

Controles mínimos

Validação
Valide corpo, parâmetros e query no servidor.
CORS
Restrinja CORS às origens necessárias.
Limites
Defina limites de corpo e de upload.
Arquivos
Não confie no nome ou tipo declarado pelo navegador.
Segredos
Guarde segredos fora do código e não os envie ao front-end.
Erros
Não exponha detalhes internos em respostas de erro.
Autenticação
Use autenticação e autorização antes de permitir operações privadas.
Abuso
Proteja endpoints contra abuso com limites e monitoramento apropriados.
Dependências
Atualize dependências com revisão de mudanças e testes.

Consistência entre banco e arquivo

Se o upload for salvo e a gravação no banco falhar, remova o arquivo órfão. Se um registro for removido, trate também o arquivo correspondente. Operações distribuídas exigem uma política explícita de compensação.
